# Prompt template: Plugin / app icon

## 适用场景

- `image_type: icon`
- 插件市场图标、应用图标、技能库标识
- 同一批次多个图标需要保持可辨识的家族感

## 先读这一段：这个模板产出的是设计稿，不是终稿

2026-07-27 用扩散模型跑过一批 11 张，逐项实测结果：

| 项 | 请求值 | 实测 |
|---|---|---|
| 尺寸 | 1024×1024 | 1254×1254（全部偏离） |
| 底色 | 单一 hex | `#F4A931` ~ `#F9A911`，且平涂不匀 |
| 字形占比 | 52–58% | 52.6% ~ 66.0%，跨 13 个点 |

**扩散模型打不准精确尺寸、精确 hex 和精确占比**，多跑几轮也不会收敛。所以本模板的定位是：

1. 用它产出字形创意与构图方向（这一步模型做得好）
2. **终稿用矢量确定性重绘**，把尺寸、底色、线宽、占比、标签排版锁死

只有第 2 步的产物才能进 `assets/` 和 plugin.json。跳过第 2 步直接交付，家族一致性必然不达标。

## SOIA 家族风格（终稿规格）

矢量重绘时按这套参数，全批次逐项一致，差异只允许出现在字形与色相：

| 参数 | 值 |
|---|---|
| 画布 | 1024×1024 |
| 外形 | 圆角方，圆角半径 230 |
| 底色 | 线性渐变，浅色停 → 深色停，方向 `x1=0 y1=0 x2=0.35 y2=1` |
| 顶部高光 | 白色渐变叠加，透明度 0.30 → 0.04 → 0 |
| 字形 | 描边式，线宽 40，`stroke-linecap/linejoin: round`，白→浅色渐变填充 |
| 字形厚度 | 本体下方 14px 处叠一层深色同形，透明度 0.38 |
| 字形中心 | Y=452，外接方框边长 470 |
| 底部标签 | Y=838，字号 108，字重 600，字距 4，白色 0.94 不透明 |

标签用小写英文短词（`coding` / `vault` / `cowork` / `env`），一到两个音节最佳；它承担辨识，字形承担记忆。

**注意**：本风格**有文字、有渐变**。这与早期版本写的「无文字、无渐变、纯扁平」相反——那版是照搬通用图标规范写的，实际做出来过于寡淡，已废弃。

## 字形选取原则

- 一个概念一个字形，不叠加两个隐喻
- 优先选已有约定俗成的符号（尖括号=代码、学士帽=课程、齿轮=环境、天平=治理）
- 避免需要文化背景才能读懂的符号
- 避免细节多到 32×32 会糊掉的字形
- **描边式字形比实心好画也好认**；实测扳手、打蛋器一类细长交叠形状容易画歪，换成循环箭头、齿轮这类中心对称形更稳

## 最终 Prompt 母本（第 1 步用）

```text
Use case: productivity-visual
Asset type: flat vector plugin icon concept

Primary request:
生成一张 1:1 的插件图标设计稿。画面主体是【字形描述】，居中构图，
除该字形外不出现任何其他元素。这是设计稿，用于确定字形创意与构图。

Style:
- 扁平矢量，几何化，描边式，线宽统一
- 背景为单一品牌色 【品牌色 hex】 平涂
- 字形为纯白 #FFFFFF，统一线宽描边
- 无阴影、无立体、无拟物、无 3D 渲染

Composition:
- 正方形画布，字形居中，四周留白等距不触边
- 缩到 32×32 时字形轮廓仍可辨认

Text accuracy:
- 设计稿阶段不要文字；标签在矢量重绘阶段统一加

Avoid:
渐变、光晕、投影、立体感、拟物材质、多色配色、写实摄影、卡通人物、
文字标签、水印、外框、多个并列元素、复杂细节。
```

## 资源落盘（终稿）

Codex 的 `interface.composerIcon` / `logo` / `logoDark` **以 plugin root 为基准解析**，不是 manifest 所在目录：

```
<plugin root>/assets/logo.png           512×512
<plugin root>/assets/composer-icon.png  32×32
```

放进 `.codex-plugin/assets/` 会让官方 `validate_plugin.py` 报 `points to a missing file`，Codex 运行时也找不到（2026-07-27 实际踩过）。

Claude Code 的 plugin.json **没有图标字段**，图标只服务 Codex 界面。

## 验收补充

除 [quality-gates.md](quality-gates.md) 的通用门外，图标批次额外检查：

1. 逐张 `view_image` 确认字形与预期一致
2. 并排比对全批次：圆角、渐变构造、线宽、字形占比、标签排版是否逐项一致
3. 缩略到 32×32 复查轮廓是否仍可辨认
4. 官方 `validate_plugin.py` 通过（资源路径与尺寸）
5. 矢量终稿由脚本生成，改色改字形重跑即可，不做后期修图

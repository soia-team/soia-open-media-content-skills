# Prompt template: Social skill catalog

## 适用场景

- `image_type: social_card | carousel`
- `preset: social_skill_catalog`
- 开源技能库、插件集合、产品能力清单的朋友圈或小红书宣传图
- 推荐一个仓库并重点推荐一个技能的双页宣传系列
- 输出必须是 imagegen 生成的完整视觉成品；需要零错字时允许只对精确字段做确定性校正

## 关键原则

社交宣传卡与康奈尔笔记一样，必须先写一份完整成品 Prompt。Prompt 不能只描述“无字主视觉”，也不能只提供统一模板和一组替换字段；每一张图都要写清楚来源、画面任务、固定空间关系、每个区域的逐字内容、图标与主视觉隐喻、材质光线、目标观感和禁区。

支持两种渲染模式：

1. `direct_poster`（默认）：把完整构图和逐字文案交给 imagegen，直接生成整张宣传海报。适合每张不超过 6 个能力项、文字密度可控、客户更看重整体视觉表现的场景。
2. `hybrid_exact_text`：仍先写完整海报 Prompt，让 imagegen 生成完整视觉设计；若技能数量、命令、URL、二维码或少量中文无法通过验收，仅对这些精确字段重做确定性文字层。不得用通用信息卡模板取代主视觉，也不得把整个版面改成扁平批量换字稿。

无论选择哪种模式，`facts.yml` 都是技能数量、名称、版本、安装命令和仓库地址的唯一真源。

信息密度指“每一块都帮助读者做判断”，不是单纯增加字数或卡片。不要用不同标题重复仓库简介；必须优先呈现可核验规模、输入、工作流、交付物、验证方式和边界。建立至少五级阅读层级，让缩略图先读到痛点或结果，而不是先读抽象分类。

## 阶段一：事实清单

先运行：

```bash
python3 scripts/build_social_catalog_facts.py \
  --repo <skill-repo> \
  --repository <owner/repo> \
  --claim-mode <total|featured> \
  --cta-mode <all|featured> \
  --output <output-dir>/facts.yml
```

- `total` 使用“当前已提供 N 个技能”；图片不需要把 N 个技能全部缩成小字，可按来源事实归并为 3–6 个清晰能力组，但文案与 manifest 必须声明 `catalog_representation: grouped-summary`。
- `featured` 使用“精选 N 个技能”，逐项展示所选技能，不得暗示为仓库总数。
- 每个能力组必须能回指至少一个真实技能；分组表作为 Prompt 的 `Content source` 一部分落盘。
- 多仓系列使用 [social-card-batch.example.yml](social-card-batch.example.yml) 明确 `include` / `exclude`，教育等排除项不得混入文案或图片。

## 推荐仓库 + 重点技能双页模式

客户要求“推荐一个仓库、重点推荐一个技能”时，设置 `narrative_mode: repository_feature_pair`，默认只生成两页：

1. `repository_recommendation`：强钩子、可核验规模、完整能力结构、重点技能判断、结果/交付形态、安装入口。
2. `featured_skill_deep_dive`：反差标题、支持输入、核心能力、真正优势、4–7 步工作流、明确交付物、验收方式、安全边界、安装入口。

生成前除 `facts.yml` 外，完整读取仓库 `README.md` 与重点技能 `SKILL.md`，落盘 `content-facts.yml`。每条卖点记录来源文件；不要根据技能名扩写。除非存在真实截图、PPT、图表或文件产物，不新增第三张“能力地图”或“证据页”。

文案钩子优先从三类中选择一种：痛点（“别让 AI 用‘应该没问题’交差”）、反差（“命令能跑，不等于环境能用”）、结果（“把散落资料变成能用的知识资产”）。避免“最近整理了”“一套技能覆盖”“形成完整闭环”等平铺开场。

## 最终 Prompt 母本

```text
Use case: ads-marketing
Asset type: 4:5 portrait social-media skill-catalog poster / carousel slide

Primary request:
根据【来源事实】设计一张完整、可直接发布的 SOIA 开源技能宣传海报。图片要让读者在手机缩略图下先看到【核心价值】，打开后能快速读懂【能力结构、重点能力、典型场景和安装入口】。不要只画一个孤立的 3D 主视觉，也不要生成没有信息层级的通用卡片模板。

Input images:
- Image 1：同系列成品风格参考，约束蓝白橙品牌色、3D 科技插画、信息密度与发光材质；不是编辑目标。
- Image 2：版式参考，约束“顶部品牌区—核心价值区—能力卡片区—重点推荐区—场景区—底部 CTA”的阅读顺序；不得复制其中示例文字。
- 如有真实截图：只作为“效果证据”插入指定区域，不得重绘、改字或伪造界面。

Canvas and visual style:
- 4:5 竖版，目标 1120 × 1400 或同等高清比例，适合朋友圈与小红书
- 蓝白为主、橙色强调；允许根据仓库主题增加一种局部辅助色，但不得破坏系列统一性
- 高质量 3D 科技插画 + 清晰商业信息图排版；不是网页截图，不是 PPT 页面，不是纯扁平 UI
- 顶部有明亮放射光、玻璃与金属质感、柔和体积光；主体边缘清楚，移动端缩略图下仍能识别
- 白色内容面板使用轻微阴影、圆角与浅蓝描边；图标统一为同一套 3D / 半立体语言
- 中文标题粗壮、对比强；正文简洁，字号不能靠缩小来塞内容

Fixed composition — preserve this reading order:

1. 顶部品牌标题条（约画布 5% 高）
- 居中深蓝圆角标题条
- 英文仓库名逐字写“【repository_display_name】”
- 白字、粗体、清晰，不添加 Logo 或随机字母

2. 核心价值区（约画布 18%–22% 高）
- 一侧放【单一主视觉隐喻】，另一侧放标题；主视觉必须和本仓库主题直接相关
- 小眉题逐字写“— 【category_label】 —”
- 主标题逐字写“【headline】”，分 1–2 行；核心词用橙色，其他文字用深蓝
- 蓝色横向副标题条逐字写“【subtitle】”
- 不要让主视觉挡住标题，不要把多个无关物体并列成素材堆

3. 能力概览区（约画布 28%–34% 高）
- 大型白色圆角面板，上缘居中放数量徽章
- 数量徽章逐字写“【claim_text】”，数字使用橙色
- 根据内容使用 2×2、3×1 或 3×2 卡片网格，每张卡包含：编号或统一图标、能力组标题、1 行短说明
- 能力组逐字使用【capability_groups】；总数较多时展示 3–6 个来源可追溯的能力组，不把全部技能名缩小硬塞
- 卡片之间留白一致，不得溢出、截字、重叠

4. 重点推荐区（约画布 16%–20% 高）
- 白色或暖白圆角框，顶部橙色胶囊标题
- 标题逐字写“★ 重点推荐：【highlight_name】 ★”
- 左侧放与重点能力相关的单一 3D 插画或真实效果预览；右侧放 4 条逐字要点【highlight_bullets】
- 要点使用橙色勾选图标，2×2 或单列排布

5. 典型场景区（约画布 8%–10% 高）
- 居中标题逐字写“— 典型场景 —”
- 横向放 4 个浅色小卡片，逐字使用【scenario_labels】
- 每个场景只表达一个用途，不写长句

6. 底部 CTA 区（约画布 10%–12% 高）
- 两条深蓝圆角横栏，第一条为安装命令，第二条为项目地址
- 标签逐字写“安装：”和“项目地址：”
- 命令逐字写“【install_command】”
- 地址逐字写“【repository_url】”
- 命令与 URL 是高风险精确字段；如果 direct_poster 无法逐字通过，保留完整画面，只切换到 hybrid_exact_text 校正这两个区域
- 未提供真实二维码目标时不要画二维码；禁止生成伪二维码

Content source:
- 仓库： 【repository】
- 来源日期与版本： 【as_of_date / package_version】
- 技能总数： 【total_skill_count】
- 声明： 【claim_text】
- 能力分组与来源技能： 【capability_group_mapping】
- 重点能力： 【highlight_name】
- 重点要点： 【highlight_bullets】
- 典型场景： 【scenario_labels】
- 安装命令： 【install_command】
- 项目地址： 【repository_url】

Text accuracy:
- 所有中文、英文仓库名、数字、命令和 URL 按 Content source 逐字渲染
- 不得把“当前已提供”改成“精选”，不得改动技能数量
- 不添加随机英文、伪 Logo、伪二维码、水印、无关平台标识或未经来源支持的能力
- 文字空间不足时优先缩短能力说明；不得缩小标题、数量和 CTA 到手机上不可读

Final effect:
像一张成熟开源项目发布海报：第一眼有明确价值和强主视觉，第二眼看懂能力结构，第三眼能找到安装入口。整体质感接近客户提供的 SOIA 蓝白橙系列成品，但每个仓库必须有自己的主视觉隐喻、构图方向和局部强调色，不能只是换标题和数字。
```

## 第二张 / 第三张轮播 Prompt 规则

轮播中的每一张都必须单独落盘完整 Prompt，不得写“沿用上一张，其余不变”。可以引用已锁定的系列风格，但必须重新写清本张的画面任务和固定构图。

### 详情 / 工作流页

- 顶部仍保留英文仓库名和本张主标题。
- 上半区用主视觉或真实效果图支持【重点能力】，旁边放支持输入、核心能力与真正优势；这些信息必须来自重点技能完整 `SKILL.md`。
- 中部画 4–7 步工作流，每步有编号、短标题和统一图标；箭头方向明确。
- 下半区放明确交付物、验证方式与使用边界，最后保留安装命令与仓库地址。
- 不重复第一页全部能力卡；本张只回答“为什么值得用”和“怎么工作”。

### 真实效果 / 证据页（可选）

- 只在存在真实截图、PPT 页面、图表或文件产物时使用。
- 2×3 或 3×3 网格展示真实效果，顶部写清“真实生成效果”或等价准确标题。
- 截图必须来自真实产物，不用 imagegen 伪造软件界面。
- 没有真实产物时只允许展示字段结构或产物形态，并逐字标注“结构示意”或“产物形态示意”；不得补写版本号、任务 ID、文件数、哈希、测试数、日期或业务数据来制造可信感。
- 底部总结 3–4 个可验证特点，并保留项目地址；无需重复大段安装命令。

## 验收与重生

1. 先检查主视觉是否真正表达仓库价值，而不是通用蓝色科技物体。
2. 再检查固定空间关系、信息层级、字号、溢出和移动端缩略图。
3. 逐字核对标题、数量、能力组、重点要点、安装命令和 URL。
4. direct_poster 文字错误时，先围绕单一问题重生一次；仍不通过再切换 `hybrid_exact_text`，只校正高风险文字区域，不重做整张模板化版面。
5. 同系列必须锁定品牌色、字体阶梯、圆角和光线；同时至少改变主视觉隐喻、构图方向、能力网格或局部强调色中的两项。
6. 检查每个区块是否增加新信息；如果删掉一个区块不影响读者判断，它就是装饰或重复，应改写或删除。
7. 扫描所有看似真实的版本号、任务 ID、文件数、哈希、测试数、日期和业务数据；无法回指来源时删除或改为明确占位结构。

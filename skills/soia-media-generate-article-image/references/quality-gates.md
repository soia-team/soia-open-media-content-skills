# Article image quality gates

每次生成后按顺序执行，任何一项失败都不能写“测试通过”。

## 1. 产物真实性

- 最终文件是 PNG/JPG/WebP 等真实位图，能读取像素尺寸。
- 本次输出目录包含落盘 Prompt、位图和 manifest。
- 非两阶段模板的正式产物目录不新增 HTML、SVG、canvas 页面或截图脚本。
- `two_stage: true` 的模板可保留确定性排版源作为可复现中间源，但最终交付必须包含真实位图；不得把 SVG、HTML 或画布文件冒充终稿。

## 2. 内容来源

- 标题、数字、人物、来源和结论能回指输入文章。
- 没有把 Agent 推测写成原文事实。
- 客户保留的个人观点区没有被代写。
- 最终 Prompt 包含注册表规定的全部 required blocks；缺一项即不进入生图。
- `social_skill_catalog` 必须先生成 `facts.yml`：技能名称和数量来自实际 `skills/*/SKILL.md`，版本来自包清单，CTA 命令由脚本编译。
- `claim_mode=total` 时显示技能必须与 `facts.yml` 全量一致；只展示子集时必须使用“精选”，不得写“当前已提供”。
- 多仓系列必须存在 `batch-facts.yml`；实际产出仓与 `include` / `exclude` 范围不一致、批次指纹不一致或同一仓同时纳入和排除均判失败。

## 3. 文字

- 将图上文字与 Prompt 的 `exact_text` 逐项人工核对。
- 中文错字、乱码、缺字、重复字、随机英文均判失败。
- 文字过小无法在目标用途下阅读判失败。
- 两阶段模板的确定性字段必须执行 OCR/机械提取并与来源逐项比对；只看原图或命令退出码不算通过。
- `social_skill_catalog` 的技能数量、技能名、安装命令、URL 和二维码不得交给扩散模型渲染。
- 二维码必须实际解码，结果与 `cta.qr_target` 完全相同；无法解码、跳转错误或未记录结果均判失败。
- `plugin_icon` 分两阶段判定：设计稿阶段图上不得有文字（有则重生成）；矢量终稿阶段
  只允许出现模板规定的底部标签，其余文字一律判失败。
- 图标终稿不接受扩散模型直出——实测尺寸、底色 hex 与字形占比均打不准，
  必须由矢量脚本重绘后再验收。

## 4. 构图与比例

- 实际像素比例与目标比例一致或在生图工具的可解释容差内。
- manifest 同时记录 requested 与 actual；生图工具只返回原生比例时必须写明差异，不得把目标比例写成已通过。
- 无裁切、遮挡、重叠、溢出、异常边框或未使用的大块死区。
- 康奈尔模板必须保持左侧问题、右侧笔记、底部回顾；左右栏塌成上下结构判失败。
- 社交卡必须按 `social-card-contract.yml` 检查平台、布局、比例、必需页角色和每页最大能力项数。
- 必须以目标平台移动端缩略尺寸复查；缩略图读不出标题或核心价值主张判失败。

## 5. 参考图一致性

- 参考图角色已明确；仅参考风格/构图时没有复制其示例内容。
- 对照参考图检查信息密度、留白、配色、手绘/像素/编辑质感。
- 只要结构正确但媒介与质感明显不符，仍判为需重生，而不是“通过”。

## 6. 版本化重生

- 失败后写新 Prompt 和新文件名，不覆盖旧位图。
- 每轮只修一个主要问题，并在 manifest 记录失败项与变化。
- 非两阶段模板禁止用代码在已生成位图上补字、遮字或重新排版。
- 两阶段模板只允许重跑确定性合成源来修正文字、二维码和品牌资产；不得直接涂改最终位图。

## 7. 批次一致性与差异

- 同一 `series_id` 锁定字体、字号阶梯、圆角、间距、标题区、CTA 区和品牌色。
- 每张主视觉至少改变主体、构图、场景或局部配色中的两项；只换标题、其他结构完全相同判为同质化失败。
- Logo 只能来自客户提供或来源明确的批准资产；扩散模型伪造的品牌标识判失败。
